## 2. Структура кейса

### Шаблон

```md
## Задача
[Боль / ограничение заказчика. Без цифр, если их нет.]

## Решение
[Что сделано и почему так. Ссылки на демо/код — если есть в frontmatter.]

## Результат
[Что проверено. Где нет метрик: TODO: цифра.]

## Стек
[Из frontmatter `stack`, списком.]

## Что бы улучшил
[Честные пробелы из текста кейса / «не проверено».]
```

### Пример: Смена (из `src/content/work/smena.mdx`)

| Блок | Текст из репо |
| --- | --- |
| **Задача** | Мастеру нужен день в Telegram: визиты, перерывы, клиенты и свободные окна — без отдельной CRM и без записи в YCLIENTS. |
| **Решение** | Mini App + бот; YCLIENTS только чтение (iCal/API); HMAC `initData`; SSRF-защита на календарном feed; `revision` против конфликтов; ноль npm-зависимостей. |
| **Результат** | Проверено: `npm test` (44), локальный `/demo`, iCal на Google Calendar, ширины 320–1060 px. Не проверено: полный iframe Telegram Web на 0.5, живой филиал YCLIENTS. **TODO: цифра** по живым мастерам / визитам в проде — в тексте нет. |
| **Стек** | Node.js 24 · SQLite · Telegram WebApp · zero npm deps |
| **Что бы улучшил** | Добить проверку в живом Telegram WebView и на реальном YCLIENTS-филиале (уже сказано в «Не проверено»). |

Сейчас в MDX часто «Задача → Решения и почему → Архитектура/Код → Результат». Предлагаю постепенно выровнять заголовки под шаблон, не ломая уникальные секции (демо, диаграммы).

## 3. Пометки «реальный клиент» / «демо» / «личный продукт»

**Сейчас в UI:** статус готовности — `готов` / `концепт` / `в разработке` (EN: shipped / concept / in progress). Это про зрелость кода, **не** про тип заказчика.

**Предложение — два независимых поля:**

| Поле | Значения | Смысл |
| --- | --- | --- |
| `status` (уже есть) | готов / концепт / в разработке | Можно ли смотреть / трогать |
| `origin` (**новое**, опционально) | `client` / `demo` / `personal` | Откуда работа |

**Как соотносятся (не подмена):**

- `origin: client` + любой `status` — заказ для бизнеса (даже если ещё «в разработке»).
- `origin: demo` — витрина / учебный контур на вымышленных данных (у Смены в подписях скринов уже «демо на вымышленных данных»).
- `origin: personal` — свой инструмент / pet (типично IP Check, часть infra).

**Черновая разметка по кейсам (нужно ваше «да/нет» по каждому — в репо нет явных «клиент X»):**

| Кейс | status сейчас | Предлагаемый origin | Почему осторожно |
| --- | --- | --- | --- |
| Приёмная | в разработке | `demo` или `client`? | Текст про шиномонтаж, но нет подтверждения «живой клиент» |
| Смена | готов | `demo` | В кейсе прямо: демо, вымышленные данные |
| Грань | концепт | `demo` | Концепт + live на поддомене портфолио |
| Зерно | концепт | `demo` | Концепт Tilda на поддомене |
| Pingo | готов | `personal` или `demo`? | Свой бот; нет строки «клиент» |
| FleetKit, crawlnet, AI Funnel, ShipCrew | готов | `personal` | Инженерные / open-source витрины |
| IP Check | готов | `personal` | Личный инструмент |

В карточке показывать **оба** ярлыка мелко: `готов · демо`, не вместо статуса.

### A. «Telegram-бот для записи клиентов»

- **Title:** Telegram-бот для записи клиентов — день мастера без отдельной CRM

- **H2:** Зачем запись в Telegram · Что видит мастер · Как отдать окна клиенту · Связка с сайтом · Сколько занимает · Когда не подходит  
- **Внутренние ссылки:** `/work/smena/` · `/work/gran/` · `/work/priemnaya/`

### B. «Сайт с онлайн-записью»

- **Title:** Сайт с онлайн-записью на первом экране  
- **Description:** Витрина, где запись — не форма «в подвале», а первый шаг: мастер, услуга, окно. Примеры: барбершоп «Грань» и сценарий после пропущенного звонка в «Приёмной».  
- **H2:** Запись на первом экране · Что должно быть выше fold · Mini App или веб-форма · Связка с днём мастера в Telegram · Ориентир по срокам и цене  
- **Внутренние ссылки:** `/work/gran/` · `/work/smena/` · `/work/priemnaya/`  
- **Не ссылаться на «Зерно»** как на пример онлайн-записи (Tilda-витрина/меню, не запись).

### C. «Автоматизация приёма заявок»

- **Title:** Автоматизация приёма заявок: с сайта в Telegram менеджеру  
- **Description:** Контур приёма лида: форма на сайте, бот, уточнения и передача менеджеру в Telegram — на примере AI Funnel Ecosystem. Рядом — мониторинг (Pingo), чтобы о простое узнавать не от клиента.  
- **H2:** Где рвётся цепочка заявка → человек · Минимальный контур · Бот, который уточняет · Уведомление менеджеру · Мониторинг рядом · Оценка объёма  
- **Внутренние ссылки:** `/work/ai-funnel-ecosystem/` · `/work/pingo/` · `/work/priemnaya/`  
- **Не обещать** «заявки не теряются» как доказанный результат; FleetKit сюда не тащить (это control plane, не приём заявок).

| --- | --- |
| Шапка `t.brand` | Богдан |

| `Person` / `personName` | Богдан Щербинин / Bogdan Shcherbinin |

**Предложение (Person не менять без вашего «да»):**

1. **Публичный бренд:** «Богдан» в шапке, «Богдан Кетасонкс» в подвале и оферте — как сейчас.

3. В политике выровнять порядок: «Богдан Кетасонкс», как в подвале.

**Нужен ваш выбор:** A) Person = Кетасонкс · B) Person = Щербинин, везде явно «также Кетасонкс» · C) оставить как есть.
