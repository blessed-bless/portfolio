## Problem

A solo barber needs the working day inside Telegram: visits, breaks, clients, and free windows — without a separate CRM and without writing back into YCLIENTS. Admin bookings sync read-only; the barber keeps personal visits and notes in Smena.

## Decisions

- **Mini App + bot.** Day / week / month, client cards, status buttons, shareable free-window text. The bot answers `/today`, `/free`, `/add`, `/find` and deep-links into the app.
- **YCLIENTS read-only.** Google Calendar iCal or the official API — no YCLIENTS password stored. The iCal URL lives in SQLite `meta`, not in exports.
- **HMAC `initData`.** Telegram signature, expiry, allow-listed ids. Eight-hour session: in-memory Bearer + HttpOnly cookie, never `localStorage`.
- **SSRF hardening on the calendar feed.** Address pinning, IP allow-list, shared timeout, socket re-check after connect.
- **Optimistic concurrency.** Forms carry a data version; a stale save from another device is rejected.
- **Snapshots and restore.** Daily DB copies; restore keeps a recovery copy first.
- **Zero npm dependencies.** Node 24 stdlib + SQLite.

## Architecture

Telegram WebApp / bot → `server.mjs` → SQLite; optional Google Calendar iCal or YCLIENTS API. Shared day math in `shared.mjs` for UI and chat.

Access: owner plus one second user (admin or assistant) via a one-time invite.
